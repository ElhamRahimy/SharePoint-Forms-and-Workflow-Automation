# IT Project Request & Lifecycle Management System (PLC)

**Microsoft SharePoint | BPC PowerForms | Nintex Workflow | JavaScript | IT Project Management | PMO | Business Process Automation**

## Project Overview

Developed an enterprise **IT Project Request & Lifecycle Management System (PLC)** to centralize and streamline the registration, evaluation, approval, execution tracking, and management of IT project requests across multiple companies and organizational departments.

The system enabled authorized users from different companies and departments to submit IT project requests through customized electronic forms.

Each request followed a structured, multi-level approval workflow involving stakeholders such as Project Managers, Operational Department Managers, PMO Specialists, and Executive Management.

Following the required approvals, accepted project requests could proceed to the implementation phase.

The solution supported multiple project lifecycle statuses and workflow scenarios, including approval, rejection, suspension, reconsideration, execution, completion, and request merging.

In addition to project request management, the system provided centralized access to project documentation, workflow history, pending tasks, and project-specific information.

The solution was implemented using **Microsoft SharePoint, BPC PowerForms, Nintex Workflow, and JavaScript**.

## Key Features

### 1. IT Project Request Registration

Designed and developed a customized electronic form for registering and managing IT project requests.

The interface enabled authorized users to submit requests and provide structured project information.

**Key Capabilities:**

- Recording project request titles and descriptions.
- Identifying requesting companies and subsidiaries.
- Recording requester information.
- Specifying project execution priorities.
- Classifying projects according to their size and type.

- Recording project stakeholders and responsible personnel.
- Specifying estimated project start and end dates.

- Submitting project requests into the approval workflow.

The structured registration process supported consistent project initiation across organizational units.

### 2. Proposed vs. Executive-Approved Project Information

Developed a dedicated interface for distinguishing between initially proposed project information and details approved by executive management.

The form included separate sections for:

- **Proposed Project Information:** Initial project planning details submitted during the request process.
- **CEO-Approved Information:** Project details confirmed or modified during executive review.

The information included organizational responsibilities, project management assignments, and estimated project schedules.

This functionality improved visibility into differences between initial project proposals and approved project arrangements.

## End-to-End Business Process

The following summarizes the main phases of the IT project request lifecycle.

### Phase 1 — Project Request Submission

An authorized user from a requesting company or department registers a new IT project request.

The form captures project details, requesting organization, proposed responsibilities, execution priority, and estimated schedule information.

### Phase 2 — Initial Review

The submitted request enters the defined approval workflow.

Relevant stakeholders review the request information and assess the proposed project.

### Phase 3 — Multi-Level Approval

The request progresses through the required approval stages involving Project Managers, Operational Department Managers, PMO Specialists, and Executive Management.

### Phase 4 — Executive Approval & Project Planning

Executive management reviews the request and confirms or modifies relevant project information.

The system maintains separate proposed and approved project details.

### Phase 5 — Reconsideration or Alternative Workflow Actions

Depending on the review outcome, the request may be approved, rejected, suspended, or returned to a previous stage for further evaluation.

The system also supports request merging where applicable.

### Phase 6 — Project Execution

Following the required approvals, the project enters the implementation phase.

Relevant project information and supporting documents remain available within the system.

### Phase 7 — Project Tracking & Documentation

Authorized users can monitor project status, access project documentation, review request history, and manage pending workflow tasks.

Project Managers, Product Owners, and PMO teams can search for projects and retrieve their associated technical documentation.

### Phase 8 — Completion & Lifecycle Tracking

Projects can be marked as completed or managed through other supported lifecycle statuses.

Request and workflow history remain available for tracking and follow-up.
